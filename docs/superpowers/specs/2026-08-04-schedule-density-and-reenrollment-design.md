# Schedule Density and Re-enrollment Design

## Goal

Make the Admin schedule substantially more compact, keep a fixed-height weekly grid when several classes share a slot, and let an administrator return a withdrawn student to the same class without counting sessions held during the withdrawal gap.

## Schedule filter layout

- The primary toolbar contains the text search, status, session type, attendance-lock state, an `Advanced filters` disclosure, the filtered result count, and a clear action.
- Class, teacher, and location selectors live in the advanced section. The section is collapsed by default unless one of those filters is active.
- Active filters remain URL-backed and appear as removable chips below the toolbar. No query contract changes are required.
- Desktop uses one compact row with wrapping at narrower widths. Mobile uses a full-width stacked disclosure; it does not require a new drawer dependency.

## Dense multi-class slots

- A week cell renders at most two compact session cards in deterministic order: active/scheduled first, completed/locked next, cancelled last; ties use start time then title.
- If more sessions exist, the cell renders a keyboard-accessible `+N lớp khác` button instead of an inner scrollbar.
- Activating that button opens an accessible modal containing every session in the cell. Each row shows title, class/teacher subtitle, time, and state tone and opens the existing session detail action.
- Week rows keep a stable height. Mobile continues to use the agenda view, where all events remain visible.
- Month view retains its existing bounded preview and overflow behavior.

## Re-enrollment model

`class_enrollments` remains the stable class/student membership referenced by attendance and result records. A new `class_enrollment_periods` table records every active interval:

- `id UUID PRIMARY KEY`
- `enrollment_id UUID NOT NULL REFERENCES class_enrollments(id) ON DELETE CASCADE`
- `started_at TIMESTAMPTZ NOT NULL`
- `ended_at TIMESTAMPTZ NULL`
- `created_by UUID NULL REFERENCES users(id) ON DELETE SET NULL`
- `ended_by UUID NULL REFERENCES users(id) ON DELETE SET NULL`
- `start_reason TEXT NULL`
- `end_reason TEXT NULL`
- timestamps and a check requiring `ended_at >= started_at`

A partial unique index permits at most one open period for an enrollment. A composite index supports temporal roster lookup. Migration 00009 backfills one period per existing enrollment using `enrolled_at` and `ended_at`.

Roster and attendance-authorization queries use an enrollment period containing the session start time. Therefore sessions before the first enrollment, during a withdrawal gap, or before a later return are excluded. Earlier attendance and scores remain unchanged.

## Re-enrollment operation

The existing enrollment status endpoint is extended additively with optional `effective_at`:

```json
{
  "status": "enrolled",
  "reason": "Học viên quay lại học",
  "effective_at": "2026-08-05T08:00:00+07:00"
}
```

- `effective_at` is accepted only when changing `withdrawn -> enrolled`; it defaults to the current server time and must fall within the class date range.
- The handler validates RFC3339 and the mandatory reason. The service remains authoritative.
- Re-enrollment requires an active student account/profile, an enrollable class, available capacity, and no active enrollment in another class of the same course.
- `completed` and `transferred` memberships cannot be reopened through this operation.
- The transaction locks the membership, opens a new period, updates the aggregate status, and writes audit plus class-operation history atomically.
- Withdrawal closes the current period at the same timestamp used for the aggregate `ended_at` value.
- The API returns the existing `Enrollment` response shape, preserving compatibility.

## Admin UI

- A withdrawn enrollment shows `Đưa trở lại lớp`.
- The confirmation modal shows the student, an effective date/time defaulting to now, and a required reason.
- The button is unavailable for completed/transferred records.
- Success invalidates class detail, enrollment list, class directory, schedule/attendance-related queries, and history.
- Conflict responses explain whether the class is full, the student is inactive, or another same-course enrollment is already active.

## Security and integrity

- The route remains ADMIN-only through the existing router group.
- All identifiers, timestamp input, transition rules, and reason length are validated at the HTTP boundary and rechecked in the service transaction.
- SQL remains parameterized and generated by sqlc.
- Audit/history records store the old/new status, effective timestamp, and new period identifier; no student PII beyond existing identifiers/codes is added.

## Verification

- Migration up/down and sqlc generation.
- Integration tests for withdrawal gap exclusion, successful same-class return, invalid transitions, capacity, inactive student, and active same-course conflict.
- Component tests for the two-card overflow behavior and re-enrollment action/modal.
- Full `make check`, database integration suite, OpenAPI lint, and browser E2E for the Admin workflow.
